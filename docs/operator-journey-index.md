# Operator Journey Index

Use this page when you know the operator goal but not the right guide. Start with the shortest path that matches the question in front of you, then move to the next proof only after the current one passes.

## Choose By Goal

| Goal                                       | Start here                                      | Pass signal                                                                                                                                                                                | Next useful path                                                                                                                                              |
| ------------------------------------------ | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Make the first authenticated local request | `docs/first-request-quickstart.md`              | `/readyz` returns `status: "ready"` and `POST /v1/requests` returns `provider: "echo"` with `model: "local-test"`.                                                                         | `docs/openai-compatible-provider-quickstart.md` for a real provider, or `docs/common-failure-modes.md` if readiness or auth fails.                            |
| Make the first real provider request       | `docs/openai-compatible-provider-quickstart.md` | `/readyz` lists `openai-compatible` and one explicit `provider: "openai-compatible"` request returns a non-empty `output`.                                                                 | `docs/operator-env-reference.md#first-real-provider-request` for provider variables, or `docs/common-failure-modes.md#provider-errors` for upstream failures. |
| Run the production-shaped deployment smoke | `docs/deployment-smoke-quickstart.md`           | `make deployment-bootstrap-secrets` creates ignored local secret files and `make deployment-smoke` proves `/readyz`, Docker health, an authenticated echo request, and startup validation. | `make deployment-status`, then `make deployment-diagnose`, when the smoke fails after startup.                                                                |
| Prove local guardrail rejections           | `docs/guardrail-verification-quickstart.md`     | Schema, policy, request-size, and budget checks return `invalid_request`, `policy_rejected`, `request_body_too_large`, and `budget_exceeded` before provider execution.                    | `docs/operator-env-reference.md#guardrails` to tune limits for another run.                                                                                   |
| Inspect observability wiring               | `docs/observability/README.md`                  | `make observability-smoke` exports gateway metrics, loads Prometheus rules, verifies targets, and provisions the Grafana dashboard.                                                        | `make observability-status` for a compact snapshot, then `make observability-inspect` for the full local wiring check set.                                    |
| Check pilot readiness                      | `docs/operator-acceptance-checklist.md`         | First request, real provider, deployment smoke, guardrail rejection, observability smoke, and `make validate` all pass in the target environment.                                          | `docs/pilot-configuration-template.md` to record the narrow pilot decisions.                                                                                  |
| Record narrow pilot decisions              | `docs/pilot-configuration-template.md`          | Provider/model policy, request guardrails, secret sources, telemetry wiring, and expected failure handling all have chosen values.                                                         | `.github/ISSUE_TEMPLATE/pilot.yml` to track those decisions in GitHub.                                                                                        |
| Create a tracked pilot issue               | `.github/ISSUE_TEMPLATE/pilot.yml`              | The issue records owner, scope, review date, deployment path, success signal, rollback trigger, runtime policy, guardrails, secrets, telemetry, and expected failure handling.             | `docs/pilot-dry-run-runbook.md` before sending real pilot traffic.                                                                                            |
| Rehearse a narrow pilot before traffic     | `docs/pilot-dry-run-runbook.md`                 | The owner records version, validation, readiness, provider, deployment, guardrail, telemetry, and go/no-go evidence.                                                                       | `docs/common-failure-modes.md` for request, provider, startup, deployment, and observability failures.                                                        |

## Common Starting Points

- New visitor: run `docs/first-request-quickstart.md`, then choose the next path from the table based on whether you need a provider, deployment smoke, guardrail proof, or pilot decision.
- Operator debugging a failed request or smoke run: open `docs/common-failure-modes.md` first, then use the linked quickstart or helper command for the failing surface.
- Team preparing a pilot: run `docs/operator-acceptance-checklist.md`, fill `docs/pilot-configuration-template.md`, open `.github/ISSUE_TEMPLATE/pilot.yml`, then complete `docs/pilot-dry-run-runbook.md`.
